The Loop

It does not call the compiler. It is the compiler.

zigttp expert embeds the repair loop inside the compiler itself. Describe the change. It proposes an edit, simulates the patch against zigts rules, reruns all 7 proofs, and stops only when the handler clears the language, the proof system, and the deployment contract it is allowed to ship.

No handoff between agent shell and compiler. The thing writing the patch is the thing proving it - and it knows when to say no.

What Ships

One binary. Five moving parts.

Compiler-agent loop in front. Pure-Zig runtime, restricted TypeScript subset, seven-check proof engine, 20 native modules, and a contract-aware deploy pipeline behind it.

01

Runtime and Performance

Pure-Zig execution tuned for HTTP handlers, with JIT, GC, pool isolation, and cold-start discipline.

pure Zig runtime x86-64 + ARM64 JIT zero-copy responses

02

Language and Type System

Restricted JavaScript and TypeScript designed to stay analyzable, with JSX, TSX, sound-mode checks, and compile-time evaluation. The type checker enforces nominal types via distinct type, discriminated union narrowing, type guard functions, readonly fields, template literal types, and generic aliases with up to 8 parameters. No classes, no exceptions, no async/await at parse time.

native TS + TSX distinct types + generics no async footguns

03

Compile-Time Analysis and Proofs

Seven-check verification suite: every path returns a Response, every Result is checked before access, reachability and dead-code detection, exhaustive match coverage, and optionals narrowed before use. Contract extraction proves behavioral properties (deterministic, read_only, idempotent) and these proof labels flow directly into runtime policy and cache decisions.

7-check verifier proof-driven cache capability-pinned sandbox

04

Virtual Modules and Native Capabilities

The standard library is Zig code exposed as zigttp:* modules for auth, validation, cache, SQL, routing, crypto, durable workflows, and more.

20 native modules declared capabilities no npm polyfills

05

Deployment and Operations

The compiler-proven contract flows into deploy: the control plane approves safe changes, requests review on capability diffs, and blocks drifted replaces before the image ever builds.

zigttp deploy contract-aware review grants + drift

06

Durable and Concurrent Execution

Keep handler code synchronous while overlapping I/O, then opt into oplog-backed durable runs with timers, signals, and crash recovery.

parallel() + race() durable run keys timers + signals

07

Developer Experience and Agent Tooling

Fetch-like handler APIs, proof cards, compiler JSON, and a native compiler-agent loop built into zigttp itself. zigts gen-tests synthesizes JSONL test cases from exhaustive execution-path enumeration. Sessions persist via JSONL event streams and replay from any checkpoint.

08

Extensibility and Embedding

Extend the runtime with third-party virtual modules or embed zigttp directly from Zig with explicit configuration.

The Provable Subset

What TypeScript looks like when it can't lie.

No classes. No exceptions. No async/await. zigts removes the parts the compiler cannot reason about, and keeps everything it can prove is correct. 

import { method, pathname, params } from "zigttp:router";

const getUser = (id: string) =>
    fetchSync(`https://api.example.com/users/${id}`)
    |> Response.json;

function handler(req) {
    return match (`${method(req)} ${pathname(req)}`) {
        "GET /"          => Response.json({ status: "ok" }),
        "GET /health"    => Response.json({ healthy: true }),
        "GET /users/:id" => getUser(params(req).id),
        "POST /echo"     => Response.json(req.body),
        _                => Response.json(
                                { error: "Not Found" },
                                { status: 404 }
                            ),
    };
}
import { parseBearer, jwtVerify } from "zigttp:auth";
import { schemaCompile, validateJson } from "zigttp:validate";
import { env } from "zigttp:env";

comptime(() => schemaCompile("user", JSON.stringify({
    type: "object",
    required: ["name", "email"],
    properties: {
        name:  { type: "string", minLength: 1 },
        email: { type: "string", format: "email" },
    }
})));

function handler(req: Request): Response {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json(
        { error: "unauthorized" }, { status: 401 }
    );

    const auth = jwtVerify(token, env("JWT_SECRET") ?? "");
    assert(auth.ok, Response.json(
        { error: auth.error }, { status: 401 }
    ));

    return match (req.method) {
        "POST" => {
            const result = validateJson("user", req.body ?? "");
            assert(result.ok, Response.json(
                { errors: result.errors }, { status: 400 }
            ));
            Response.json({ user: result.value }, { status: 201 });
        },
        _ => Response.json({ user: auth.value }),
    };
}

import { guard } from "zigttp:compose";
import { parseBearer, jwtVerify } from "zigttp:auth";
import { env } from "zigttp:env";

distinct type Secret = string;
type Claims = { sub: string };
type AuthRequest = Request & { user?: Claims };
const jwtSecret: Secret = env("JWT_SECRET") ?? "";

const cors = (req: AuthRequest): Response | undefined =>
    match (req.method) {
        "OPTIONS" => Response.text("", {
            status: 204,
            headers: { "Access-Control-Allow-Origin": "*" }
        }),
        _ => undefined,
    };

const requireAuth = (req: AuthRequest): Response | undefined => {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json(
        { error: "unauthorized" }, { status: 401 }
    );
    const auth = jwtVerify(token, jwtSecret);
    if (!auth.ok) return Response.json(
        { error: auth.error }, { status: 403 }
    );
    req.user = auth.value;
    return undefined;
};

const dashboard = (req: AuthRequest): Response =>
    Response.json({ welcome: req.user?.sub ?? "guest" });

// Pipe: guards short-circuit, handler runs last
const handler = guard(cors) |> guard(requireAuth) |> dashboard;
import { run, step, waitSignal } from "zigttp:durable";
import { decodeJson } from "zigttp:decode";
import { schemaCompile } from "zigttp:validate";

comptime(() => schemaCompile("order", JSON.stringify({
    type: "object",
    required: ["item", "qty"],
    properties: {
        item: { type: "string" },
        qty:  { type: "number", minimum: 1 }
    }
})));

function handler(req: Request): Response {
    const body = decodeJson("order", req.body ?? "");
    assert(body.ok, Response.json(
        { errors: body.errors }, { status: 400 }
    ));

    return run(`order-${body.value.item}`, () => {
        const charge = step("charge", () =>
            fetchSync("https://pay.api/charge", {
                method: "POST",
                body: body.value
            })
        );
        // Wait for external webhook confirmation
        const confirm = waitSignal("payment-confirmed");
        return Response.json({
            status: "fulfilled",
            chargeStatus: charge.status,
            signal: confirm
        });
    });
}

Good Questions

The fast objections.

What most developers want answered before committing to a restricted subset.

How is zigttp different from Node.js, Deno, and Bun?

Node.js, Deno, and Bun run the full language spec. zigttp implements a restricted subset (zigts) that removes classes, exceptions, and async/await at parse time. The restrictions let the compiler prove handler correctness, generate least-privilege sandboxes, and replay executions deterministically. Those properties require a closed language surface, which is why general-purpose runtimes cannot offer them.

What does "proves your code correct" actually mean?

The compiler walks every execution path and runs a seven-check verification suite: control flow completeness (every path returns a Response), property access validation, reachability analysis, dead code detection, Result value access before checking, exhaustive match coverage, and handler contract extraction. From those checks it proves behavioral properties (deterministic, read_only, idempotent) and stamps them as labels on the deployed artifact. These are static proofs over the restricted language subset, not lint heuristics.

Can I use npm packages with zigttp?

No. zigttp ships 20 virtual modules implemented in Zig instead. The compiler tracks every module import to generate least-privilege sandboxes. For anything the virtual modules do not cover, call an external API with fetchSync.

How do I install zigttp?

Run the one-line installer from the README, or download a tarball from the GitHub releases page. Source builds require Zig 0.16.0.

Is it free and open source?

Yes. zigttp is MIT licensed and available on GitHub. The entire runtime, compiler, and standard library of virtual modules are open source.
