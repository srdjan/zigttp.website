TypeScript, minus the footguns.

zts is the TypeScript subset that makes compile-time verification possible. Remove the features that prevent static analysis. Keep everything you need for handlers.

Supported

  • let / const declarations
  • if / else / switch / for...of
  • Arrow functions and destructuring
  • Template literals and spread
  • match expressions (exhaustive)
  • Pipe operator |>
  • guard() composition
  • comptime() evaluation
  • Optional chaining ?. and nullish coalesce ??
  • Type annotations (stripped at compile)
  • JSX / TSX (first-class SSR)

Banned at parse time

  • class / this - use plain objects
  • while / do...while - use for...of
  • try / catch / throw - use Result types
  • var - use let or const
  • null - use undefined
  • == / != - use === / !==
  • new - use factory functions
  • async / await - I/O is synchronous
  • delete - use destructuring
  • any / as - use proper types
  • regex - use string methods or zigttp:text

A handler is a function that returns a response.

No middleware chains. No decorator magic. No hidden state. Write a function, return a response, ship it. 

import { routerMatch } from "zigttp:router";

const routes = {
    "GET /":            getHome,
    "GET /health":      getHealth,
    "GET /users/:id":   getUser,
    "POST /echo":       postEcho,
};

function handler(req) {
    const match = routerMatch(routes, req);
    if (match) {
        req.params = match.params;
        return match.handler(req);
    }
    return Response.json(
        { error: "Not Found" },
        { status: 404 }
    );
}
import { parseBearer, jwtVerify } from "zigttp:auth";
import { schemaCompile, validateJson } from "zigttp:validate";

schemaCompile("user", JSON.stringify({
    type: "object",
    required: ["name", "email"],
    properties: {
        name:  { type: "string", minLength: 1 },
        email: { type: "string", minLength: 5 },
    }
}));

function handler(req) {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json(
        { error: "unauthorized" }, { status: 401 }
    );

    const auth = jwtVerify(token, "my-secret");
    if (!auth.ok) return Response.json(
        { error: auth.error }, { status: 401 }
    );

    if (req.method === "POST") {
        const result = validateJson("user", req.body);
        if (!result.ok) return Response.json(
            { errors: result.errors }, { status: 400 }
        );
        return Response.json({ user: result.value }, { status: 201 });
    }

    return Response.json({ user: auth.value });
}
import { guard } from "zigttp:compose";
import { parseBearer, jwtVerify } from "zigttp:auth";
import { env } from "zigttp:env";

const cors = (req) => {
    if (req.method === "OPTIONS") return Response.text("", {
        status: 204,
        headers: { "Access-Control-Allow-Origin": "*" }
    });
    return undefined;
};

const requireAuth = (req) => {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json({ error: "unauthorized" }, { status: 401 });
    const auth = jwtVerify(token, env("JWT_SECRET") ?? "");
    if (!auth.ok) return Response.json({ error: auth.error }, { status: 403 });
    req.user = auth.value;
    return undefined;
};

const dashboard = (req) =>
    Response.json({ welcome: req.user.sub });

// Pipe: guards short-circuit, handler runs last
const handler = guard(cors) |> guard(requireAuth) |> dashboard;
import { run, step, waitSignal } from "zigttp:durable";
import { decodeJson } from "zigttp:decode";
import { schemaCompile } from "zigttp:validate";

schemaCompile("order", JSON.stringify({
    type: "object",
    required: ["item", "qty"],
    properties: {
        item: { type: "string" },
        qty:  { type: "number", minimum: 1 }
    }
}));

function handler(req) {
    const body = decodeJson("order", req.body);
    if (!body.ok) return Response.json(
        { errors: body.errors }, { status: 400 }
    );

    return run(`order-${body.value.item}`, () => {
        const charge = step("charge", () =>
            fetchSync("https://pay.api/charge", {
                method: "POST",
                body: JSON.stringify(body.value)
            })
        );
        // Wait for external webhook confirmation
        const confirm = waitSignal("payment-confirmed");
        return Response.json({ status: "fulfilled", id: confirm.id });
    });
}

What zigttp is and isn't

What exactly is zigttp?

zigttp is a TypeScript runtime built from scratch in Zig, designed specifically for serverless and FaaS workloads. It compiles your handler into a single 1.2MB binary with zero dependencies, achieving 3ms cold starts and 80K requests per second throughput. The compiler proves 7 safety properties about your handler before it runs.

How is zigttp different from Node.js, Deno, and Bun?

Node.js, Deno, and Bun are general-purpose runtimes that support the full language specification. zigttp takes the opposite approach: it implements an opinionated TypeScript subset that removes footgun features (classes, this, exceptions) at parse time and replaces async/await with sync-looking code backed by Zig's async I/O. This constraint enables compile-time verification of handler correctness, automatic least-privilege sandboxing, durable execution, and deterministic replay - none of which are possible when the runtime must support arbitrary TypeScript.

What does "proves your code correct" actually mean?

The compiler walks every possible execution path through your handler and checks 7 properties statically. It proves every path returns a Response, every Result is checked before access, no module-scope state leaks between requests, no unvalidated input reaches sensitive sinks, match expressions are exhaustive, and optionals are narrowed before use. These are not type hints or linter rules - they are exhaustive proofs derived from the restricted language subset.

Can I migrate from Node.js or Express?

zigttp is not a drop-in replacement for Node.js. It implements a restricted TypeScript subset and does not support npm packages or the Node.js API. However, if your serverless handlers are stateless request-response functions, the migration path is straightforward: rewrite handlers using zigttp's functional style and virtual modules. The result is a provably correct, single-binary deployment with dramatically lower cold starts.

Is it free and open source?

Yes. zigttp is MIT licensed and available on GitHub. The entire runtime, compiler, and standard library of virtual modules are open source.

What are virtual modules?

Virtual modules (zigttp:auth, zigttp:cache, zigttp:sql, zigttp:io, etc.) are built-in capabilities implemented in Zig with zero interpretation overhead. They replace npm packages for common serverless needs: JWT authentication, key-value caching, SQLite queries, parallel I/O, durable execution, and more. The compiler tracks every virtual module call for automatic sandboxing.

What is zts?

zts is the TypeScript subset that zigttp supports. It removes features that prevent compile-time analysis - classes, try/catch, while loops, null, async/await, regex - and adds features that enable it: match expressions, pipe operator, guard() composition, and comptime() evaluation. The restrictions are what make the 7 compile-time proofs possible. Every banned feature has a recommended replacement that works within the verification model.

How do I install zigttp?

Three ways: curl -fsSL https://zigttp.timok.com/install.sh | sh works on macOS and Linux, brew install zigttp/tap/zigttp for Homebrew users, or npm install -g zigttp if you prefer npm. All methods install the same zigttp CLI binary. Run zigttp doctor after installation to verify your setup.

Can I use npm packages with zigttp?

No. zigttp does not support npm packages or the Node.js module system. Instead, it provides 18 virtual modules (zigttp:auth, zigttp:cache, zigttp:sql, zigttp:crypto, etc.) implemented in native Zig. This eliminates supply chain risk and enables the compiler to track every capability your handler uses for automatic sandboxing. If you need functionality not covered by a virtual module, use fetchSync to call an external API.
