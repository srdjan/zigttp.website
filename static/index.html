Compiler-in-the-loop agent

The compiler won't let the agent guess.

How the loop runs

  1. 01 Write

    The agent drafts a handler from your request.

  2. 02 Compile

    It runs the same proof pass that gates deploys.

  3. 03 Read diagnostics

    Unsupported code comes back with a file, line, and fix.

  4. 04 Rewrite

    It edits against the compiler output and tries again.

  5. Proven

    The handler clears the proof loop before you review it.

Core idea

Three claims, all concrete.

01

Provable TypeScript

zigts removes the features that hide control flow: while, try/catch, class, var. That buys the compiler up to 13 properties per handler, from every path returns to no secret leaks.

02

Compiler-in-the-loop agent

zigttp expert writes a patch, runs the proof pass, reads diagnostics, and rewrites until the compiler accepts it.

03

Small Zig binaries

zigttp deploy emits a local self-contained binary. Current public baseline: 4.8 MB and 7-15 ms typical cold start.

CLI surface

Five commands cover the proof loop.

Init a handler, prove it on save, test it, ask the compiler-guided agent for edits, then deploy a signed local binary.

safe safe_with_additions blocked needs_review
