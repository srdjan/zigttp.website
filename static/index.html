TypeScript, minus the footguns.

zigts is the TypeScript subset zigttp compiles. It drops features that block static analysis and adds constructs (match, pipe, guard, comptime) that make the 7 proofs possible.

Supported

  • let / const declarations
  • if / else / for...of
  • Arrow functions and destructuring
  • Template literals and spread
  • match expressions (exhaustive)
  • Pipe operator |>
  • guard() composition
  • assert statements (type narrowing)
  • distinct type declarations (nominal safety)
  • comptime() evaluation
  • Optional chaining ?. and nullish coalesce ??
  • Type annotations (stripped at compile)
  • JSX / TSX (first-class SSR)

Banned at parse time

  • class / this - use plain objects
  • while / do...while - use for...of
  • switch / case - use match expressions
  • try / catch / throw - use Result types
  • var - use let or const
  • null - use undefined
  • == / != - use === / !==
  • new - use factory functions
  • async / await - I/O is synchronous
  • delete - use destructuring
  • any / as - use proper types
  • regex - use string methods or zigttp:text

A handler is a function that returns a response.

Plain functions, explicit data flow, and the compiler verifying the result. Four examples showing how handlers look in practice. 

import { routerMatch } from "zigttp:router";

const routes = {
    "GET /":            getHome,
    "GET /health":      getHealth,
    "GET /users/:id":   getUser,
    "POST /echo":       postEcho,
};

function handler(req) {
    const match = routerMatch(routes, req);
    if (match) {
        req.params = match.params;
        return match.handler(req);
    }
    return Response.json(
        { error: "Not Found" },
        { status: 404 }
    );
}
import { parseBearer, jwtVerify } from "zigttp:auth";
import { schemaCompile, validateJson } from "zigttp:validate";

schemaCompile("user", JSON.stringify({
    type: "object",
    required: ["name", "email"],
    properties: {
        name:  { type: "string", minLength: 1 },
        email: { type: "string", minLength: 5 },
    }
}));

function handler(req) {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json(
        { error: "unauthorized" }, { status: 401 }
    );

    const auth = jwtVerify(token, "my-secret");
    if (!auth.ok) return Response.json(
        { error: auth.error }, { status: 401 }
    );

    if (req.method === "POST") {
        const result = validateJson("user", req.body);
        if (!result.ok) return Response.json(
            { errors: result.errors }, { status: 400 }
        );
        return Response.json({ user: result.value }, { status: 201 });
    }

    return Response.json({ user: auth.value });
}
import { guard } from "zigttp:compose";
import { parseBearer, jwtVerify } from "zigttp:auth";
import { env } from "zigttp:env";

const cors = (req) => {
    if (req.method === "OPTIONS") return Response.text("", {
        status: 204,
        headers: { "Access-Control-Allow-Origin": "*" }
    });
    return undefined;
};

const requireAuth = (req) => {
    const token = parseBearer(req.headers["authorization"]);
    if (!token) return Response.json({ error: "unauthorized" }, { status: 401 });
    const auth = jwtVerify(token, env("JWT_SECRET") ?? "");
    if (!auth.ok) return Response.json({ error: auth.error }, { status: 403 });
    req.user = auth.value;
    return undefined;
};

const dashboard = (req) =>
    Response.json({ welcome: req.user.sub });

// Pipe: guards short-circuit, handler runs last
const handler = guard(cors) |> guard(requireAuth) |> dashboard;
import { run, step, waitSignal } from "zigttp:durable";
import { decodeJson } from "zigttp:decode";
import { schemaCompile } from "zigttp:validate";

schemaCompile("order", JSON.stringify({
    type: "object",
    required: ["item", "qty"],
    properties: {
        item: { type: "string" },
        qty:  { type: "number", minimum: 1 }
    }
}));

function handler(req) {
    const body = decodeJson("order", req.body);
    if (!body.ok) return Response.json(
        { errors: body.errors }, { status: 400 }
    );

    return run(`order-${body.value.item}`, () => {
        const charge = step("charge", () =>
            fetchSync("https://pay.api/charge", {
                method: "POST",
                body: JSON.stringify(body.value)
            })
        );
        // Wait for external webhook confirmation
        const confirm = waitSignal("payment-confirmed");
        return Response.json({ status: "fulfilled", id: confirm.id });
    });
}

What zigttp is and isn't

What is new in zigttp v0.16.0-rc2?

Pre-built binaries for Linux and macOS, and a built-in agentic coding loop in the CLI. The runtime itself is unchanged: same proofs, same binary size, same virtual modules.

What exactly is zigttp?

zigttp is a TypeScript runtime built from scratch in Zig, designed specifically for serverless and FaaS workloads. It compiles your handler into a single 1.2MB binary with zero dependencies, and v0.16.0-rc2 is the first release that ships as a single binary for Linux and macOS.

How is zigttp different from Node.js, Deno, and Bun?

Node.js, Deno, and Bun run the full language spec. zigttp implements a restricted subset (zigts) that removes classes, exceptions, and async/await at parse time. The restrictions let the compiler prove handler correctness, generate least-privilege sandboxes, and replay executions deterministically. Those properties require a closed language surface, which is why general-purpose runtimes cannot offer them.

What does "proves your code correct" actually mean?

The compiler walks every execution path and checks 7 properties: every path returns a Response, every Result is checked before access, module-scope state does not leak between requests, unvalidated input never reaches sensitive sinks, match expressions cover all variants, and optionals are narrowed before use. These are static proofs over the restricted language subset, not lint heuristics.

Can I migrate from Node.js or Express?

zigttp does not support npm or the Node.js API, so it is not a drop-in swap. If your handlers are stateless request-response functions, rewriting them in zigts is usually direct. You get compile-time proofs and a 1.2MB binary with 3ms cold start in exchange for giving up the npm ecosystem.

Is it free and open source?

Yes. zigttp is MIT licensed and available on GitHub. The entire runtime, compiler, and standard library of virtual modules are open source.

What are virtual modules?

Virtual modules (zigttp:auth, zigttp:cache, zigttp:sql, zigttp:io, etc.) are built-in capabilities implemented in Zig with zero interpretation overhead. They replace npm packages for common serverless needs: JWT authentication, key-value caching, SQLite queries, parallel I/O, durable execution, and more. The compiler tracks every virtual module call for automatic sandboxing.

What is zigts?

zigts is the TypeScript subset that zigttp supports. It removes features that prevent compile-time analysis - classes, try/catch, while loops, switch, null, async/await, regex - and adds features that enable it: match expressions, pipe operator, guard() composition, assert statements, and comptime() evaluation. The restrictions are what make the 7 compile-time proofs possible. Every banned feature has a recommended replacement that works within the verification model.

How do I install zigttp?

Run the one-line installer from the README, or download a tarball from the GitHub releases page. Source builds require Zig 0.16.0-dev.

Can I use npm packages with zigttp?

No. zigttp ships 18 virtual modules (zigttp:auth, zigttp:cache, zigttp:sql, zigttp:crypto, etc.) implemented in Zig instead. The compiler tracks every module import to generate least-privilege sandboxes. For anything the virtual modules do not cover, call an external API with fetchSync.
