Most coding agents generate, then hope tests catch what they got wrong. zigttp expert calls the same verifier that gates your deploys: it writes a handler, compiles it, reads the proof errors, and rewrites until every obligation is discharged. The loop closes before the code reaches you.

  • Every patch is compiled and proven, never just generated.
  • Unsupported or unsafe patterns are rejected at the source, with the compiler's own errors as the feedback signal.
  • You review proven handlers, not plausible drafts.

How the loop closes

  1. 01 Write

    The agent drafts a handler in zigts from your request.

  2. 02 Compile

    It runs the real zigttp compiler, not a linter approximation.

  3. 03 Read proof errors

    Unsupported or unproven patterns return as compiler errors.

  4. 04 Rewrite

    It edits against those errors and recompiles until they clear.

  5. Proven

    Every obligation discharged before the code reaches you.

Every deploy appends a contract verdict to proofs.jsonl:

safe safe_with_additions blocked needs_review 
# scaffold and prove on every save
zigttp init api && cd api
zigttp dev --watch --prove

# enforce the handler's active guarantees in CI
zigttp ratchet check src/handler.ts

# deploy a self-contained binary locally, with a ledger entry
zigttp deploy
zigttp proofs show HEAD

# keep regressions pinned
zigttp witnesses replay
zigttp expert "add health check"
