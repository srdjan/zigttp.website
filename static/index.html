Proof loop

Same handler, live verdicts, no separate spec file.

The handler declares its obligations in the type surface. Every save recompiles, narrows Results, checks match coverage, extracts the contract, and compares the new surface to the running version.

  • Studio shows verdict, active Spec set, contract diff, and witnesses.
  • Unsafe changes block hot swap and print the contract difference.
  • Counterexamples persist so regressions replay instead of rediscovering.

Compiler-in-the-loop agent

The first agent that writes against the compiler, not around it.

Most coding agents generate, then hope tests catch what they got wrong. zigttp expert calls the same verifier that gates your deploys: it writes a handler, compiles it, reads the proof errors, and rewrites until every obligation is discharged. The loop closes before the code reaches you.

  • Every patch is compiled and proven, never just generated.
  • Unsupported or unsafe patterns are rejected at the source, with the compiler's own errors as the feedback signal.
  • You review proven handlers, not plausible drafts.
